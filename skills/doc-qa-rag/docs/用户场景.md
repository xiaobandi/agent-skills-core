# 用户场景

按「谁 → 什么情况下 → 说什么 → 得到什么 → 注意什么」组织。每个场景都能照着跑一遍。

---

> ⚠️ 本技能尚未填写真实场景（`scenarios`），下面为**通用推导**，信息量有限。

## 场景一 · 轻量客服与 FAQ 数字员工的日常用法

- **角色**：轻量客服与 FAQ 数字员工
- **触发时机**：需要「文档问答 RAG」这件事有结果的时候
- **他会说**：`用 doc-qa-rag 帮我文档问答`
- **需要准备**：知识库文件（md/txt/csv 等）；用户问题
- **拿到什么**：带引用的回答 + 未覆盖问题提示
- **容易踩的坑**：把模型自身知识与库内知识混着答是最危险的失分点

---

## 场景二 · 换成你自己的材料

同一句话，把材料换成你手头的真实数据即可：

```text
用 doc-qa-rag 处理下面这份材料：
<粘贴你的内容 / 贴文件路径>
```

**输入结构不要改**：字段名变了，脚本会读不到；缺字段时应当被明确告知缺什么，而不是猜。

| 字段 | 必填 | 说明 |
|---|---|---|
| 知识库文件（md/txt/csv 等） | ✅ | 缺失会导致输出不可用 |
| 用户问题 | ✅ | 缺失会导致输出不可用 |
| 回答长度 | ⬜ | 有则更好 |
| 是否只答库内内容 | ⬜ | 有则更好 |

---

## 场景三 · 边界情况（重要）

这几条写清楚做不到什么，比列一堆能力更有用：

- 不做库外知识补充，除非用户明确要求并标注
