# 用户场景

按「谁 → 什么情况下 → 说什么 → 得到什么 → 注意什么」组织。每个场景都能照着跑一遍。

---

> ⚠️ 本技能尚未填写真实场景（`scenarios`），下面为**通用推导**，信息量有限。

## 场景一 · 用户反馈聚合分析师的日常用法

- **角色**：用户反馈聚合分析师
- **触发时机**：需要「评论情绪识别 / 评价情感分析」这件事有结果的时候
- **他会说**：`用 review-sentiment-tag 帮我情绪分析`
- **需要准备**：评论流（每行一条或表格）
- **拿到什么**：带标签的评论表 + 汇总
- **容易踩的坑**：'物流慢但东西好'是混合情绪，单纯二分会失真

---

## 场景二 · 换成你自己的材料

同一句话，把材料换成你手头的真实数据即可：

```text
用 review-sentiment-tag 处理下面这份材料：
<粘贴你的内容 / 贴文件路径>
```

**输入结构不要改**：字段名变了，脚本会读不到；缺字段时应当被明确告知缺什么，而不是猜。

| 字段 | 必填 | 说明 |
|---|---|---|
| 评论流（每行一条或表格） | ✅ | 缺失会导致输出不可用 |
| 历史申诉记录 | ⬜ | 有则更好 |
| 品类专属词 | ⬜ | 有则更好 |

---

## 场景三 · 接进自动化链路

脚本是纯函数（文件进 / stdout 出 / 退出码表达判定），可以直接被 CI、定时任务调用：

```bash
python3 scripts/sentiment_tag.py --file examples/input/reviews.txt
```

| 退出码 | 含义 | 链路里应该怎么做 |
|---|---|---|
| 0 | 通过 | 继续下一步 |
| 1 | 警告 | 记入待办，不阻塞 |
| 2 | 阻断 | **中断流程**并转人工 |
