用户场景

按「谁 → 什么情况下 → 说什么 → 得到什么 → 注意什么」组织。每个场景都能照着跑一遍。

场景一 · 短视频脚本创作师

  • 角色：短视频脚本创作师
  • 触发时机：接到一个新选题，要在 60–90 秒口播里抢住前 3 秒
  • 他会说：用 hook-copy 给「出租屋改造：不改墙不打钉，只靠气味换氛围」写钩子，受众是独居租房党，发小红书
  • 拿到什么：6 条钩子（含类型 / 机制 / 适用场景）+ 优先 A/B 测试建议
  • 注意什么：钩子不能和正文对不上——高点击低完播会被平台反噬

场景二 · 私域 / 公众号运营

  • 角色：私域 / 公众号运营
  • 触发时机：同一批内容要分发到多个平台，各平台标题字数限制不同
  • 他会说：同一个选题，帮我出小红书（≤20 字）和公众号（≤64 字）两版钩子
  • 拿到什么：两套按平台字数修剪过的钩子，机制标注保持一一对应
  • 注意什么：小红书受字数限制，信息要更集中；公众号可以留长一点铺垫

场景三 · 内容团队负责人

  • 角色：内容团队负责人
  • 触发时机：要复盘上一批内容为什么有的爆有的不爆
  • 他会说：把上个月 12 条笔记的钩子按机制分类，看哪类完播最好
  • 拿到什么：按机制维度的归类结果（需你提供各条完播数据）
  • 注意什么：没有完播数据时，本技能只给分类、不给结论——不编造效果

场景四 · 换成你自己的材料

同一句话，把材料换成你手头的真实数据即可：

用 hook-copy 处理下面这份材料：
<粘贴你的内容 / 贴文件路径>

输入结构不要改：字段名变了，脚本会读不到；缺字段时应当被明确告知缺什么，而不是猜。

字段必填说明
内容主题✅缺失会导致输出不可用
目标受众✅缺失会导致输出不可用
平台⬜有则更好
人设语气⬜有则更好
历史高完播钩子⬜有则更好
