# 平台格式适配

把同一份主稿按目标平台的语境、字数、结构与标签规则重排，产出多个可直接发布的版本。

## 输入

- **必需**：主稿（标题 + 正文）；目标平台列表
- **可选**：各平台历史爆款风格；账号人设语气

若缺少必需输入，**明确告诉用户缺什么，不要猜**。信息不足时的默认行为是提问。

## 环境探测与降级

> 本节是本技能跨平台可用的关键。执行前先判断当前环境能力，再选路径。
> **不要假设任何平台专有的工具名。**

按顺序探测以下能力，记录可用结果：

| 能力 | 首选路径 | 降级路径 |
|---|---|---|
| 读取工作区文件 | 平台原生文件读取 | 请用户直接粘贴内容 |
| 执行代码 | 运行 `scripts/check_env.py` 获取能力清单，再跑本技能脚本 | 按正文规则手工推导，跳过脚本 |
| 生成二进制文件（docx/xlsx/pdf/图片） | 调用平台的文档/图像能力或 `scripts/` | 输出 Markdown 或参数说明，注明需用户自行转换 |
| 联网检索 | 平台检索能力 | 仅用用户提供的材料，不臆造外部信息 |
| 外部系统接入 | 平台连接器 / MCP | 引导用户手动导出数据后粘贴 |

规则：

- 能力可用时静默使用，**不要向用户播报探测过程**。
- 主路径不可用时走降级路径，并在交付物末尾用一行说明用了哪条降级路径及原因。
- 全部路径都不可用时，明确告知用户当前环境缺少什么，并给出替代方案。

## 执行步骤

1. 确认目标平台清单
2. [脚本] 运行 format_adapter.py 做机械重排（字数/结构/标签）
3. 在机械版之上做语境改写：同一观点在各平台的表达习惯不同
4. 给每个平台标注适用的配图/封面要求
5. 输出各平台版本，不合并

### 配套脚本

`scripts/` 下为本技能自带的确定性脚本（仅标准库、可独立运行）：

- `scripts/format_adapter.py`
- `scripts/check_env.py`

脚本只承担可机检的机械环节，判断与创作仍由模型完成。输出细节、参数与边界情况见 `scripts/` 内各脚本头部 docstring。

## 输出格式

按平台分段的多个版本，每段含标题 / 正文 / 标签 / 语气提示。这是「技能」区别于一次性 prompt 的核心——输出必须可预测。

```
## 【平台 A】
标题：…
正文：…
标签：…
## 【平台 B】 …
```

### 数值与事实纪律

> 本节对全部技能生效。创作型技能最容易违反的就是这一条。

- 输出中出现的**任何具体数字**（数量、金额、比例、百分比、日期、时长、粉丝数、条数），
  必须能在输入或已确认的材料中找到出处。
- 材料未提供时，输出 `<待填>` 占位符并**说明需要用户补什么**，
  **不得自行估计、换算或凭常识补全**。
- 人名、机构名、平台政策、价格规则等具体事实同理：未提供则不臆造，必要时改为向用户提问。
- 骨架（含表格列名）中出现的字段，若材料无对应数据，该字段填 `<待填>`——
  **不得因为「骨架里有这一列」就补一个看起来合理的数据**。
- 本条优先于「把结构写完整」——**宁可留空，不可编造**。
  一个带 `<待填>` 的可信交付物，优于一个数字齐全但全是编的交付物。

### 业务红线

> 本节对全部技能生效。以下每一条都是真实业务里踩过并付过代价的。

- **不披露成本与供应链**：对外交付物中不得出现成本明细、进货价、供应商名称与联系方式
  （内部向经营者本人汇报除外）。
- **隐私必须脱敏**：用户手机号、地址、订单号、真实姓名出现在对外内容中一律脱敏；
  内部记录也不原样留存完整号码。
- **不贬低竞品**：可陈述公开可比的事实，不做贬损评价，不引用未经核实的竞品参数，
  不泄露自家底价应对比价。
- **舆情升级即转人工**：出现平台投诉、公开曝光、监管举报等威胁时一律转人工，
  不在公开渠道纠缠，也不就地做超授权承诺。
- **安全类审慎归因**：涉及人身安全的反馈（起火、冒烟、漏液、过敏等），
  不得简单归因为「使用不当」，先给可验证的安全说明与处置建议。
- **不越权承诺**：赔偿、折扣、退款、权益、时效，凡未获授权的，一律留空待确认。
- **引用先校验时效**：引用知识库 / FAQ / 政策 / 价目前，先确认是否为现行版本；
  过期内容不得直接引用，也不得当作事实陈述。
- **数据先查异常**：处理数据前先做异常值检查（单位错误、量级突变、重复记录、跨期混算），
  发现异常先标记再分析，不把脏数据直接当结论。
- **分类须声明边界**：涉及分类 / 分层 / 归类的输出，须说明档位是否互斥、是否穷尽；
  存在重叠或空档时必须显式指出，不得默默凑数。
- **跨对象不挪用**：同一材料库存在多个业务对象（如线上商品与线下门店）时，
  引用任何参数、价格、数量都须指认其归属对象，不得跨对象直接套用。

## 使用示例

```text
输入（示例）：
  - 主稿（标题 + 正文）：<填入实际内容>
  - 目标平台列表：<填入实际内容>

输出（示例）：
  按「输出格式」段落给出的骨架逐段填充，
  每段结论均可追溯到输入，不含未提供依据的断言；
  输入未提供的具体数字一律写成 <待填>，不自行估计。
```

> 示例只示结构。真实使用时请按用户提供的材料填充，不要照抄示例中的占位内容。

## 质量检查

交付前逐条自查：

- [ ] 每个版本都满足该平台字数上限
- [ ] 未把平台名写进正文（适配是改写不是贴标签）
- [ ] 输出中的具体数字均有输入出处；缺失处已写 `<待填>`，未自行估计
- [ ] 所有数据与事实可追溯到输入，无编造
- [ ] 输出结构与「输出格式」一致

## 已知陷阱

<!-- v2-script-traps -->

- 标签**只取主稿里真实出现过的**，脚本不补假标签（v1 会用写死的 `#话题 #干货 #分享` 补齐）；不足时给告警。
- `PLATFORMS` 是**内部基线而非平台官方规则**，产出带 `rules_source/rules_version`；正式发布前用 `--rules` 传入已核验的规则，不在产出里把基线当官方规定引用。
- 只改字数不改语气，等于没适配——小红书要口语和第一人称，公众号要有小标题分层
- 机械截断会把结尾的转化钩子砍掉，需人工复核

> 这一节记录真实跑过之后踩到的坑。规范明确推荐把环境特有的反直觉事实（同名不同义、静默失败、单位不一致等）写在这里——它比写在别处更容易被读到。

## 边界

- 不做自动发布，只产出可发布文本
- **不做**：超出上述范围的事；不确定时先问用户。
- **信息不足时**：提问，不编造。
