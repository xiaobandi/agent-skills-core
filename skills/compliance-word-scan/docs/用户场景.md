# 用户场景

按「谁 → 什么情况下 → 说什么 → 得到什么 → 注意什么」组织。每个场景都能照着跑一遍。

---

> ⚠️ 本技能尚未填写真实场景（`scenarios`），下面为**通用推导**，信息量有限。

## 场景一 · 电商 AI 商品视觉的日常用法

- **角色**：电商 AI 商品视觉
- **触发时机**：需要「平台合规词扫描」这件事有结果的时候
- **他会说**：`用 compliance-word-scan 帮我合规扫描`
- **需要准备**：待检文案（或图片 OCR 后的文本）；目标平台
- **拿到什么**：违规清单表 + 放行结论（放行 / 警告 / 阻断）
- **容易踩的坑**：语境豁免：'最好喝的一家店'（口语表达）与 '最好'（绝对化用语）风险不同，不要一律替换

---

## 场景二 · 换成你自己的材料

同一句话，把材料换成你手头的真实数据即可：

```text
用 compliance-word-scan 处理下面这份材料：
<粘贴你的内容 / 贴文件路径>
```

**输入结构不要改**：字段名变了，脚本会读不到；缺字段时应当被明确告知缺什么，而不是猜。

| 字段 | 必填 | 说明 |
|---|---|---|
| 待检文案（或图片 OCR 后的文本） | ✅ | 缺失会导致输出不可用 |
| 目标平台 | ✅ | 缺失会导致输出不可用 |
| 商品类目 | ⬜ | 有则更好 |
| 历史违规记录 | ⬜ | 有则更好 |
| 平台最新规则清单 | ⬜ | 有则更好 |

## 场景三 · 接进自动化链路

脚本是纯函数（文件进 / stdout 出 / 退出码表达判定），可以直接被 CI、定时任务调用：

```bash
python3 scripts/compliance_scan.py --file examples/input/draft.txt --platform 淘宝
```

| 退出码 | 含义 | 链路里应该怎么做 |
|---|---|---|
| 0 | 通过 | 继续下一步 |
| 1 | 警告 | 记入待办，不阻塞 |
| 2 | 阻断 | **中断流程**并转人工 |

## 场景四 · 边界情况（重要）

这几条写清楚做不到什么，比列一堆能力更有用：

- 不替代平台官方审核，只做发布前自查
- 不判断商标/专利侵权等法律问题，遇到标注并转人工
