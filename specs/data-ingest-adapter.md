# Spec · 数据对接（`data-ingest-adapter`）

> **本能力有意不进 `skills/`**。报告裁定：报告明确"数据采集连接器族不公共化为 SKILL"——开源侧只发 Spec + Mock + 权限声明。
> 因此这里只发 **Spec + Mock + 权限声明**，实现留在各员工仓库的绑定层。

## 为什么公共化它反而更糟

这一族能力与**外部平台接口**强绑定（各平台字段、限频、鉴权都不同）。
若做成一个公共 SKILL，会出现"一份提示词要同时适配 N 个平台"的局面，
最终每个平台的分支逻辑都塞进同一份正文，可读性和可测性双输。

正确的切法是：**接口适配留在连接器层**，SKILL 层只处理"拿到数据之后做什么"。

## Spec（员工侧绑定必须满足）

| 项 | 要求 |
|---|---|
| 输入 | 平台返回的原始结构（字段名以各平台文档为准） |
| 产出 | 归一化后的统一结构 `{source, collected_at, items[]}` |
| 幂等 | 同一时间窗重复拉取结果一致 |
| 限频 | 遵守平台文档给出的 QPS 与配额 |
| 失败 | 超时/限频/鉴权失败分别给出可区分的错误码，不得静默返回空 |
| 脱敏 | 命中 PII 字段先脱敏再入库 |

## Mock（供本仓测试使用）

`tests/fixtures/data-ingest-adapter.json` 提供一份脱敏样例，字段结构与真实响应一致。
**测试只允许用 Mock**，不得在 CI 里打真实平台。

## 权限声明

| 权限 | 用途 | 是否必需 |
|---|---|---|
| 只读读取 | 采集数据用于分析与产出 | 必需 |
| 写入/发布 | **本能力不申请** | — |

所有写操作一律由人工确认后执行，不在本能力的权限范围内。
